## なぜ束ねると安定するのか

同じ精度の予測器 `M` 個の平均を取ります。各予測器の分散を `σ²`、予測器どうしの相関を `ρ` とすると、平均の分散はこう書けます。

```math
\operatorname{Var}\Bigl(\frac{1}{M}\sum_{m=1}^{M} h_m\Bigr)
= \frac{1 - \rho}{M}\,\sigma^{2} \;+\; \rho\,\sigma^{2}
\qquad (M = @M:M@)
```

**この 1 本の式に、アンサンブルのすべてが入っています。**

- 第 1 項は `M`（木の本数）を増やせば 0 に近づく。
- 第 2 項は `M` をいくら増やしても消えない。**下限は `ρσ²`** です。

だから本数を増やすと途中で頭打ちになります。そこから先へ進むには **`ρ` を下げる（木どうしを似ないようにする）しかありません**。

| 手法 | `ρ` を下げる工夫 |
|---|---|
| バギング | 訓練データを復元抽出で変える |
| ランダムフォレスト | それに加えて **各分岐で使う特徴量もランダムに絞る** |

ランダムフォレストがバギングより強いのは、精度を上げたからではなく **相関を下げたから** です。式の第 2 項を直接叩いています。バイアスは変わらず、バリアンスだけが減ります。

## ブートストラップと OOB

`n` 件から復元抽出で `n` 件引くとき、ある 1 件が一度も選ばれない確率は

```math
\Bigl(1 - \frac{1}{n}\Bigr)^{n} \;\xrightarrow[n \to \infty]{}\; e^{-1} \approx 0.368
```

**各木は平均して全体の約 63.2% しか見ていません。** 残り約 36.8% はその木にとって未知のデータなので、そこで測ったスコアが **OOB スコア** です。交差検証を別に回さなくても汎化性能が推定できる、という副産物が得られます。

## ブースティング — 関数空間の勾配降下法

ブースティングは、モデルを 1 本ずつ足していきます。

```math
F_m(x) = F_{m-1}(x) + @nu:\nu@ \, h_m(x)
```

`h_m` は「いまの予測 `F_{m-1}` に対する損失の負の勾配」に当てはめた木です。

```math
r_i^{(m)} = -\left.\frac{\partial L(y_i, F)}{\partial F}\right|_{F = F_{m-1}(x_i)}
```

二乗誤差なら `r = y - F`、つまり **残差** そのものです。「前の木が間違えたところを次の木が学ぶ」の正体は、パラメータではなく **関数を勾配方向に更新している** ことです（ラボ 3 と同じ式が、関数の空間で回っています）。

`ν` は学習率（`learning_rate`）で、1 歩の大きさです。

```math
\nu \downarrow \;\Longrightarrow\; M \uparrow
```

**学習率を下げたら本数を増やす** 必要があるのは、歩幅を縮めた分だけ歩数が要るからです。`ν = 0.05, M = 1000` あたりが実務でよく使われる組み合わせです。

## LightGBM / XGBoost の葉の値

損失を 2 次まで展開すると（`g` は 1 次、`h` は 2 次の微分）、葉ごとの最適な出力値が閉じた形で出ます。

```math
w_j^{*} = -\frac{\sum_{i \in I_j} g_i}{\sum_{i \in I_j} h_i + \lambda}, \qquad
\text{分岐の利得} = \frac{1}{2}\left[\frac{G_L^{2}}{H_L+\lambda} + \frac{G_R^{2}}{H_R+\lambda} - \frac{G^{2}}{H+\lambda}\right] - \gamma
```

分母の `λ` が正則化、末尾の `γ` が「葉を 1 枚増やすための最低利得」です。**利得が `γ` に届かない分岐は行われない** — これが木の枝刈りにあたります。ハイパーパラメータ `reg_lambda` / `min_split_gain` はここに入ります。

## 特徴量の重要度

**不純度ベース**（`feature_importances_`）は、その特徴量で分岐したときの不純度減少を全木で合計したものです。

```math
\mathrm{Imp}(j) = \sum_{\text{全木}} \sum_{\text{$j$ を使った分岐 } s} \frac{n_s}{n}\,\Delta G(s)
```

分岐の候補が多い特徴量（連続値、カテゴリ数の多い列）ほど「たまたま良い切れ目」が見つかりやすく、**過大評価される偏り** があります。

**Permutation Importance** は定義が素直です。列 `j` の値だけをシャッフルして、性能の落ち幅を測ります。

```math
\mathrm{PI}(j) = s(\text{元データ}) - \frac{1}{K}\sum_{k=1}^{K} s\bigl(\text{列 } j \text{ をシャッフルしたデータ}\bigr)
```

**「その列が無くなったら、どれだけ困るか」をそのまま測っています。** ただし相関の強い列が 2 本あると、片方を壊してももう片方が代役を務めるため、**両方とも重要度が低く出る** という弱点があります。
