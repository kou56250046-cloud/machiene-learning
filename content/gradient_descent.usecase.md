## どこで動いているのか

勾配降下法は、ほぼすべての学習の内側で回っています。

| 場面 | 使われ方 |
|---|---|
| ニューラルネットの学習 | すべての重みをこの式で更新する。実質これしかない |
| ロジスティック回帰・線形 SVM | 大規模データでは解析解を諦めて SGD で解く（`SGDClassifier`） |
| 勾配ブースティング | 「関数空間の勾配降下」。1 本の木が 1 歩にあたる |
| 行列分解・レコメンド | 評価値の再現誤差を SGD で下げる |
| ハイパーパラメータ以外のすべて | 損失が微分できるなら、まずこれ |

## 手法の選び方（実務の既定値）

| 用途 | 既定 | 補足 |
|---|---|---|
| とりあえず動かす | **Adam** `lr = 1e-3` | 迷ったらこれ。多くの実装の初期値 |
| Transformer / 言語モデル | **AdamW** `lr = 1e-4 〜 3e-4` + ウォームアップ | 重み減衰を分離した版 |
| 画像分類で最高精度を狙う | **SGD + Momentum 0.9** `lr = 0.1` + Cosine 減衰 | 最終精度は Adam をやや上回ることが多い |
| 微調整（ファインチューニング） | Adam `lr = 1e-5 〜 5e-5` | 事前学習を壊さないよう桁を下げる |

## 学習率スケジューリング

現場では学習率を固定しません。

- **ウォームアップ** — 最初の数百ステップだけ `η` を 0 から線形に上げる。初期は勾配が暴れやすく、いきなり大股だと発散するためです。
- **Cosine 減衰 / Step 減衰** — 進むにつれて歩幅を縮める。大まかな谷を見つけてから底を詰める、という順序です。
- **ReduceLROnPlateau** — 検証損失が数エポック改善しなければ `η` を 1/10 にする。実装が簡単で効果が出やすい定番です。

## 学習が失敗したときの読み方

損失曲線の形から、原因はかなり絞れます。

| 症状 | 原因 | 対処 |
|---|---|---|
| 損失が `NaN` になる | 学習率が大きすぎる／数値が発散 | `η` を 1/10 に。勾配クリッピング |
| 損失が上下に激しく振動 | 学習率が大きい／バッチが小さい | `η` を下げる、バッチを増やす |
| 損失がほぼ横ばい | 学習率が小さすぎる／勾配消失 | `η` を 10 倍、初期化・正規化層を見直す |
| 途中まで下がって止まる | 谷底付近、または鞍点 | 減衰を入れる、Momentum を上げる |
| 訓練だけ下がり検証が上がる | 過学習（ラボ 2） | 早期打ち切り、正則化 |

**最初にやるのは学習率を 10 倍・1/10 して両方試すこと。** ほかのどのハイパーパラメータよりも、まずここが効きます。

## ひとつ具体例を追う

> **画像分類の再学習（1 万枚、10 クラス）**

1. Adam `lr = 1e-3` で開始 → 3 エポック目で損失が `NaN`。バッチ内に極端に明るい画像があり、勾配が跳ねていた。
2. 勾配クリッピング（ノルム 1.0 で頭打ち）を追加 → `NaN` は消えたが、検証精度が 72% で頭打ち。
3. **学習率探索**（`lr` を 1e-6 から 1 まで対数的に上げ、損失が最も急に下がる区間を読む）で `3e-4` を選択。
4. Cosine 減衰と 500 ステップのウォームアップを追加 → 検証精度 81%。**モデル構造は一度も変えていません。**

最適化の設定だけで数ポイント動く、というのは珍しくありません。モデルを大きくする前に、ここを詰めるほうが安上がりです。

## このラボで試してほしいこと

1. 「お椀」で `lr` を少しずつ上げ、**発散が始まる境界値** を見つける。その値がその地形の `2/λ_max` です。
2. 「細長い谷」で SGD と Adam を切り替える。同じステップ数でどれだけ差が出るかが、条件数の悪さの代償です。
3. 「凸凹」で出発点を数か所変えて降ろす。**乱数シードを変えると結果が変わる** という現象を、目で見て納得しておくと、実験ログ（ラボ 12）で「シードを記録する」意味が腑に落ちます。
