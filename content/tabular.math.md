## 前処理は「関数」である

前処理は、訓練データから **統計量を推定する関数** です。ここを意識できるかどうかが、リークを防げるかどうかを分けます。

```math
z = \frac{x - \mu}{\sigma}, \qquad
x_{\text{欠測}} \leftarrow \operatorname{median}(x_{\text{訓練}})
```

`μ, σ, median` は **データから推定したパラメータ** であって、定数ではありません。だから「訓練データだけで推定し、検証データにはその値を適用する」必要があります。

```math
\hat{\theta} = \mathrm{fit}(X_{\text{train}}), \qquad
X'_{\text{valid}} = \mathrm{transform}(X_{\text{valid}};\, \hat{\theta})
```

全データで `fit` してから分割すると、`θ̂` に検証データの情報が入ります。これが **データリーク** です。パイプラインは、この順序を機械的に守らせる仕組みです。

## カテゴリ符号化の次元

水準数 `L` のカテゴリ列を One-Hot にすると、列が `L`（ドロップすれば `L-1`）本に増えます。

```math
d_{\text{new}} = d_{\text{num}} + \sum_{c \in \text{cat}} \bigl(L_c - 1\bigr)
```

都道府県（47）× 職業（20）× 商品カテゴリ（120）なら、それだけで 184 列。**`p/n` が悪化する**（ラボ 2）ので、水準の多い列は上位だけ残して残りを「その他」に畳む、ターゲット符号化を使う、といった対処が要ります。

順序符号化は 1 列で済みますが、`S=0, M=1, L=2` という **大小関係を勝手に導入します**。線形モデルはこれを真に受け、木モデルは「しきい値で切る」だけなので影響が小さい — 標準化の要否と同じ理由です。

## 木モデルが標準化を必要としない理由

線形モデル・kNN・SVM は、予測が特徴量の **値そのもの** に依存します。

```math
f(x) = \sum_j w_j x_j + b
```

`x_j` の単位が 1000 倍になれば `w_j` は 1/1000 になり、正則化項 `Σw_j²` の効き方が列ごとに変わってしまいます。だから標準化が必須です。

対して木モデルの分岐は `x_j ≤ t` という **順序** の判定だけです。単調変換（標準化、対数変換）で順序は変わらないので、

```math
x_j \le t \iff \frac{x_j - \mu}{\sigma} \le \frac{t - \mu}{\sigma}
```

**結果が数学的に一致します。** 木モデルに標準化を掛けるのは無害ですが無意味です。

## LightGBM が速い理由

厳密な分岐探索は、各特徴量について全ての切れ目を試すので `O(n·d)` 掛かります。LightGBM は値を `B`（既定 255）個のビンに丸めてヒストグラムを作ります。

```math
O(n \cdot d) \;\longrightarrow\; O(B \cdot d) \quad (B \ll n)
```

ヒストグラムを一度作れば、分岐の利得はビンの累積和だけで計算できます。さらに片方の子のヒストグラムは **親から兄弟を引く** だけで求まるので、計算量が半分になります。数百万行でも数十秒で学習が終わるのは、この 2 つの工夫によります。

## 交差検証の平均とばらつき

```math
\bar{s} = \frac{1}{K}\sum_{k=1}^{K}s_k, \qquad
\mathrm{SD} = \sqrt{\frac{1}{K-1}\sum_k (s_k - \bar{s})^{2}}, \qquad
\mathrm{SE} = \frac{\mathrm{SD}}{\sqrt{K}}
```

箱ひげ図の箱の高さが `SD` にあたります。**モデル A と B の平均差が `2·SE` に届かないなら、その差は分割の運の範囲内** です。

さらに厳密に比べるなら、同じ分割で測ったスコアの **差** を取って（対応のある比較）、その差の平均がゼロから離れているかを見ます。

```math
t = \frac{\overline{d}}{\mathrm{SE}(d)}, \qquad d_k = s_k^{A} - s_k^{B}
```

同じ分割を使うと分割そのもののばらつきが打ち消され、小さな差でも検出しやすくなります。**モデル比較では、必ず同じ `random_state` の分割を使い回してください。**

## SHAP — 寄与を公平に分ける

1 件の予測 `f(x)` を、各特徴量の寄与 `φ_j` の和に分解します。

```math
f(x) = \phi_0 + \sum_{j=1}^{d}\phi_j
```

`φ_0` は全体の平均予測。`φ_j` は協力ゲーム理論のシャープレイ値で、**「その特徴量を加えたときの予測の変化」を、あらゆる順序について平均した値** です。

```math
\phi_j = \sum_{S \subseteq N \setminus \{j\}}
\frac{|S|!\,(d - |S| - 1)!}{d!}\,\bigl[f(S \cup \{j\}) - f(S)\bigr]
```

全部分集合を回るので厳密計算は `2^d` 通りですが、木モデルには多項式時間の厳密解法（TreeSHAP）があります。**「足し合わせると予測値そのものになる」ことが保証されている** のが、他の重要度にはない性質です。だから 1 件ごとの説明に使えます。
