## ここで何をしているか

機械学習の仕事のうち、モデルを選んで学習させる部分はごく一部です。実際に時間を取られるのは、**データをどこから取り、どう置き、どう取り出すか**。このページはその土台にあたります。

流れは 3 段階です。

1. **取得** — 公開 API から取ってきて、表（データフレーム）の形にする
2. **蓄積** — Parquet ファイルとして `data/raw/` に置く
3. **検索** — DuckDB で SQL を打つ

サーバーは 1 つも立てません。全部ローカルのファイルです。止め忘れも課金もありません。

## なぜ Parquet なのか

CSV ではなく Parquet を使っています。理由は 3 つです。

| | CSV | Parquet |
|---|---|---|
| 型 | 全部が文字列。読むたびに推測が要る | 列ごとに型を保存する |
| サイズ | そのまま | 列単位で圧縮され、数分の 1 になる |
| 読み出し | 常に全部読む | **必要な列だけ**読める |

10 年ぶんの気象データ（約 3,600 行 × 8 列）でも数十 KB に収まります。「平均気温の列だけ欲しい」というとき、Parquet は他の列を読み飛ばせます。行数が増えるほど差が開きます。

## なぜ DuckDB なのか

DuckDB は **サーバーの要らない SQL エンジン** です。PostgreSQL のようにプロセスを立てる必要がなく、ライブラリとして呼ぶだけで動きます。

さらに重要なのが、**Parquet を直接 SQL で読める**ことです。

```sql
SELECT * FROM read_parquet('data/raw/weather_tokyo.parquet');
```

「まず DB に取り込む」という手順が丸ごと不要になります。このページでは保存済みの Parquet を自動でビューとして登録しているので、`SELECT * FROM weather_tokyo` とテーブル名だけで書けます。

pandas でも同じ集計はできますが、**結合・グループ化・ウィンドウ関数は SQL のほうが短く書けて速い**ことが多く、そしてこの書き方はそのまま実務で通用します。

> SQL 欄は読み取り専用にしてあります。`SELECT` と `WITH` で始まる文しか通しません。カタログ画面から元データを壊せないようにするためです。

## 取得条件を必ず一緒に残す

Parquet と並べて `<name>.meta.json` を書いています。中身は「いつ・どこから・どんな条件で取ったか」です。

```json
{
  "source": "Open-Meteo (archive-api.open-meteo.com)",
  "fetched_at": "2026-08-28T07:12:00+00:00",
  "rows": 3650,
  "params": { "city": "tokyo", "start": "2015-01-01", "end": "2026-08-25" }
}
```

これが無いと、半年後に `weather_tokyo.parquet` を見ても**どの期間のどの都市か分からない**データになります。データそのものより、その来歴のほうが先に失われます。「保存済みデータ」タブの「取得条件」から、いつでも確認できます。

## 5 つの取得元

| 取得元 | 種類 | キー | 何に使うか |
|---|---|---|---|
| 公開データセット | テーブル | 不要 | 分類・回帰の練習。通信不要で必ず動く |
| 気象データ | 時系列 | 不要 | 季節性・トレンド分解・時系列予測 |
| 株価・指数 | 時系列 | 不要 | ノイズが支配的な時系列。気象と好対照 |
| ニュース記事 | テキスト | 不要 | 形態素解析・TF-IDF・トピックモデル |
| 政府統計 e-Stat | テーブル | **要** | 実データらしい欠測・表記ゆれの前処理 |

e-Stat だけは無料の利用登録が要ります。取得元で e-Stat を選ぶと、取り方の手順が画面に出ます。

**気象と株価を両方入れて比べてみてください。** 気象は 1 年周期がはっきり出るのに対し、株価はほとんどランダムに見えます。同じ「時系列」でも予測のしやすさがまるで違うことが、グラフ 1 枚で分かります。

## データを git に入れない理由

`data/raw/` は `.gitignore` で除外しています。

- **取り直せる** — API を叩けば同じものが手に入る
- **すぐ古くなる** — 株価もニュースも毎日変わる
- **リポジトリが膨らむ** — git はバイナリの差分を圧縮できず、履歴に永久に残る

一方で `.meta.json` に取得条件を残しているので、**同じ条件で取り直せば同じデータが再現できます**。コードと条件だけを版管理し、データそのものは持たない、という考え方です。

## この先の使い道

ここに溜めたデータが、これから作るドメイン別ラボの入力になります。

- **テーブルデータラボ** — 公開データセットや e-Stat を使って、欠測処理・カテゴリ変数・特徴量エンジニアリング・モデル解釈（SHAP）
- **時系列ラボ** — 気象と株価で、季節分解・自己相関・ラグ特徴量・`TimeSeriesSplit`
- **テキストラボ** — ニュース記事で、形態素解析・TF-IDF・共起ネットワーク・トピックモデル

まずは公開データセットを 1 つと、気象を 1 都市ぶん入れておくのがおすすめです。
